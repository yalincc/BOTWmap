# Xnavi 信标协议 v1

guest 插件与宿主读取层的单一契约。结构体见 `xnavi-beacon/beacon.h`，
宿主 Go 镜像见 `xnavi/beacon.go`。两者须逐字段一致。

> **实现说明**：下文 §1 描述的 beacon.json/pos.json 文件通道最终未采用——
> 插件写文件会与游戏文件系统服务争用导致卡死。实际实现为纯内存信标：
> 插件把 64 字节写入静态缓冲，宿主 `beaconDiscover` 扫描进程可读写内存区、
> 按魔数定位并缓存地址后直读（tier1）；tier2(pos.json)/tier3(内存扫描) 保留为回退。
> 世界坐标取 MainBody 矩阵平移分量 m[3]/m[7]/m[11]。详见 plugin/README.md。

## 1. 通道总览
```
guest(exlaunch subsdk9)
  每帧   : 写 64B xnav_beacon_t 到自分配堆页（guestVA）
  init   : 写 sdmc:/xnavi/beacon.json（含 guestVA，一次；重分配时重写）
  每200ms: 写 sdmc:/xnavi/pos.json（兜底，best-effort 非阻塞）
宿主 EdenTracker.Start（每 tick，Attach 门后）
  tier1 RAM : arenaLow+guestVA 直读 64B → 校验 → publishState(source="beacon")
  tier2 文件: 读 pos.json → 新鲜度门 → publishState(source="beacon-json")
  tier3 扫描: 现有 scanNear/锁定状态机（完全保留，不动）
```
sdmc 在宿主的真实路径：`<edenDir>/user/sdmc/xnavi/`（edenDir 由进程自省
`processExePath` 取得，模式同 `platform_eden.go SaveRoots`）。

## 2. RAM 信标（64B 小端，详见 beacon.h）
| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | magic | u32 | 0x56414E58 "XNAV" |
| 4 | schema | u16 | 1 |
| 6 | build | u16 | mod 构建号 |
| 8 | seq | u32 | 帧计数，每写 +1 |
| 12/16/20 | x/y/z | f32 | 世界或本地坐标 |
| 24 | yaw | f32 | 朝向弧度（v1 宿主暂不发布，后续增量） |
| 28 | state | u32 | 0大世界1神庙2试炼3菜单4加载5死亡6回忆 |
| 32 | gameClock | u64 | 游戏时间编码 |
| 40 | actorPtrHash | u32 | 诊断 |
| 44 | crc | u32 | CRC32-IEEE of bytes[0,44) |
| 48/52 | hp/stamina | f32 | 可选 |
| 56 | flags | u32 | bit0 grounded |
| 60 | reserved | u32 | 保留 |

CRC：多项式 0xEDB88320，初值 0xFFFFFFFF，终值取反 == Go `hash/crc32.ChecksumIEEE`。

## 3. beacon.json（init 一次）
```json
{"magic":"XNAV","schema":1,"build":1,"guestVA":"0x2109ABCD00","ts":1795000000.0}
```
- guestVA：信标页 guest 虚拟地址（hex 字符串），须落在堆窗口
  [0x2000000000,0x3000000000)（线性别名已实证区间）。
- 宿主据此算 host = arenaLow + guestVA；arenaLow = findEdenDram 返回锚点。

## 4. pos.json（每 200ms 兜底）
```json
{"magic":"XNAV","schema":1,"build":1,"seq":12345,
 "x":3757.7,"y":342.8,"z":2157.6,"yaw":1.23,"state":0,
 "gameClock":0,"hp":12.0,"stamina":3.0,"flags":1,
 "ts":1795000000.123}
```
- ts：unix 秒（float）。新鲜度门：now - ts <= 3s。
- JSON 通道用 ts+seq 判活，不做 CRC（字段级冗余足以判新鲜）。

## 5. 校验与判活
- magic/schema 不符 → 该 tier  miss。
- RAM：CRC 不符 → miss；seq 冻结 >3s（插件停摆）→ miss。
- 坐标按 state 选校验器：state∈{1,2} → ShrineCoordOK；否则 WorldCoordOK。
  （声明式 state 直接决定校验尺度，消灭进庙/站桩启发式。）
- tier1/2 命中即 verified=true（插件数据权威，跳过扫描器 moveN 运动确认）。
- 每 tick 即便 seq 未变也持续 publish，保持 state.age 新鲜供 GUI。

## 6. 缓存与自愈
- arenaLow/hostAddr 缓存；magic 失败或 attach 变化时重推导（游戏重启重映射）。
- beacon.json 周期重读（~5s 或失败时），拾取 guestVA 变更。
- 三级回退：tier1 miss→tier2；tier2 miss→tier3 现有扫描器（语义不变）。
- tier1/2 恢复后清除扫描器旧锁定状态，避免与信标打架。

## 7. 兼容性
- 纯 exefs 信标 mod，不碰 romfs → 与 UKMM romfs mod/金手指无冲突。
- subsdk9 避开 BOTW Optimizer 的 subsdk3 → 共存。
- 信标 mod 缺失/未启用时，宿主自动落 tier3，旧功能完全不受影响。
