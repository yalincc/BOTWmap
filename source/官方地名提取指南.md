# 官方简体中文地名提取指南

> 本文档记录如何从《塞尔达传说：旷野之息》游戏文件中提取官方简体中文地名，避免下次走弯路。
> 关联：`游戏文件数据记录.md`（本项目用到的游戏数据全景）；`官方地名核对.md`（核对结论）。

## 目标

从游戏 RomFS 中提取 `LocationMarker.msbt`，获取官方简体中文地名对照表（label → 中文名）。

## 工具

| 工具 | 用途 | 位置 |
|---|---|---|
| Ryujinx 模拟器 | 提取游戏 RomFS | 用户自行安装 |
| sarc_tool | 解包 SARC/pack 文件 | `G:\YUZU\格式转换工具\sarc_tool\` |
| Python | 解析 MSBT 文件 | 系统自带 |

## 步骤

### 1. 提取 RomFS

用 Ryujinx 模拟器的「提取 RomFS」功能，将游戏文件导出到本地目录。

- 游戏 XCI：`G:\YUZU\Switch Games\The Legend of Zelda Breath of the Wild [01007EF00011E000] [v1114112] (1G+1U+2D).xci`
- 提取输出：`G:\YUZU\Switch Games\RomFS`

### 2. 解包简体中文语言包

简体中文语言包位于：
```
G:\YUZU\Switch Games\RomFS\Pack\Bootup_CNzh.pack
```

用 sarc_tool 解包：
```bash
cd "G:\YUZU\Switch Games\RomFS\Pack"
"G:\YUZU\格式转换工具\sarc_tool\sarc_tool.exe" Bootup_CNzh.pack
```

解包后输出到同名目录：
```
Bootup_CNzh/
  Message/
    Msg_CNzh.product/
      StaticMsg/
        LocationMarker.msbt   ← 这就是地名字典！
```

### 3. 解析 LocationMarker.msbt

MSBT 原始文件保留在 `source/LocationMarker.xmsbt`（解包后拷贝，改名防误写）。
解析产物 `source/简体中文地名表.csv`（label, simplified_chinese，692 条）已提交在库中，无需重新解析。

如需重新解析，按下方「MSBT 格式要点」自行写解析脚本（原 `parse_msbt.py` 已随调试脚本清理，产物 csv 即权威）。

## MSBT 格式要点

### 文件结构

MSBT 是 Nintendo Switch 的消息文本格式，小端序。

```
文件头 (0x00)
  Magic: "MsgStdBn" (8 bytes)
  BOM: 0xFFFE (little-endian)
  ...

Section 1: LBL1 (Label 表)
Section 2: TXT2 (文本表)
```

### TXT2 Section（文本表）

```
Magic: "TXT2" (4 bytes)
Section Size (u32)
Padding (8 bytes) = 0
Number of Texts (u32)           ← 偏移 +16
Text Offset Table (4 bytes/text) ← 偏移 +20，共 num_texts * 4 字节
Text Data (null-terminated UTF-16LE)
```

**关键：text offset 是相对于 `Number of Texts` 字段的位置（即 section 开头 + 16），不是相对于 text_offset_table！**

### LBL1 Section（标签表）

```
Magic: "LBL1" (4 bytes)
Section Size (u32)
Padding (8 bytes) = 0
Number of Groups (u32)          ← 偏移 +16
Group Offset Table (8 bytes/group) ← 偏移 +20
  每个 group: num_labels(u32) + label_table_offset(u32)
```

Label 条目结构：
```
Label Length (1 byte)
Label String (length bytes, ASCII)
Text Index (u32)
```

## 踩过的坑

### 1. SARC 是嵌套的

外层 SARC 包里嵌套了内层 SARC（Yaz0 压缩），sarc_tool 自动处理了这层，不需要手动解压 Yaz0。

### 2. MSBT section 开头有 8 字节 padding

LBL1 和 TXT2 section 开头都有 8 字节 padding，不是 4 字节。num_groups / num_texts 在 +16 的位置，不是 +12。

### 3. TXT2 的 text offset 基准

text offset 不是相对于 text_offset_table，也不是相对于 section 开头，而是相对于 `Number of Texts` 字段的位置（即 section 开头 + 16）。

这个是最坑的点，调了很久才发现。验证方法：找到一个已知中文名，反推 text offset 的基准。

### 4. label 遍历方式

LBL1 的 group 结构比较复杂（hash 分组），与其遍历 group 表，不如直接用已知 label 列表去文件里搜索 label 字符串，然后读前面的长度字节和后面的 text index。这样更简单可靠。

## 下次如果要更新地名

1. 重新提取 RomFS（如果游戏更新了）
2. 重新解包 `Bootup_CNzh.pack` → 取新 `LocationMarker.msbt` 覆盖 `source/LocationMarker.xmsbt`，重新解析出 `简体中文地名表.csv`
3. 运行 `python source/build_official_fix.py` 生成新的修正清单
4. 核对 `source/官方修正清单.csv` 后运行 `python source/apply_official_fix.py` 更新 `regions.js`
