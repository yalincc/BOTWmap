# xnavi-pc

《塞尔达传说：旷野之息》PC 移植版（Savage Wind Recomp）的定位导航。
单文件、零依赖、纯只读，网页互动地图与存档进度体系沿用 BOTWmap 现有那一套，无需改动。

## 形态与交付

- **GUI 版（独立发布包）**：`xnavi-pc.exe`（GUI 外壳，改自 xnavi-gui）+ `xnavi-core.exe`（本工程编译的 Savage Wind PC 核心），发布包位于 `RELEASE/xnavi-pc-v3.2.2.zip`。
- **命令行版**：双击本目录 `xnavi-pc.exe`（由 `main.go` 编译），控制台打印 + 自动打开地图/状态页。

## 定位核心技术与机制

> **2026-11-06 换血**：不再写死任何堆偏移。旧方案（固定 `0x24486FBA8`）能跑但游戏一更新就废，
> 且失效时红点会"定格在旧位置仍显示已定位"。现方案见 `docs/spec/LOCATE-SAVAGEWIND.md`。

### 1. 静态指针链 + 结构漏斗（跨版本自愈）
- **基址**：Savage Wind 把 guest 地址空间固定映射在 `0x7000000000`，宿主地址 = `0x7000000000 + guest VA`。
- **注意映射是稀疏的**：映射起始处只有约 3.2GB，而玩家坐标在 guest VA 9.7GB 处；任何"固定窗口"都会漏，必须逐段枚举。
- **玩家对象**：`+0x00` 指向静态区（类型）、`+0xD8` 三个 float32 世界坐标、`+0x120` 自指（链表头）。
- **判别漏斗**（实测唯一）：静态区出站指针目标 15 万 → `+0xD8` 是合法坐标 ~200 → `+0x120` 自指 **1 个**。
- **成本**：扫静态区 49MB / 49ms + 十几万次小读 ≈ **220ms**；冷启动就是靠它秒锁。

### 2. 三层降级（写权限收归一处）
- **L0 缓存槽**：`xnavi-pc-chain.json` 存构建指纹 + 静态槽位，指纹一致直接读，微秒级；
- **L1 静态区重找**：L0 校验不过（游戏重启/更新）时现场重跑漏斗，约 220ms；
- **L2 全窗口兜底**：L1 也归零时，用真值锚点（游戏日志 `[place]` / F10）扫全部 guest 区，1.5~3 秒；
- 每 2 秒做结构深度校验（`+0x00` 静态指针 + `+0x120` 自指），结构没坏就不重扫（玩家站着不动是正常状态）。

### 3. 进出神庙尺度法（Shrine Hold，保留）
- **判据**：`isShrineScale = (|X| < 300 && |Z| < 300 && Y < 50)`；实测神庙内坐标为 `-75.50/15.70/75.50` 这类小值；
- 进庙时大世界坐标突变（位移 > 100m）→ 红点**钉在神庙入口**，不透传地下局部坐标；出庙自动恢复。

### 4. F10 屏幕坐标校准（真值锚点，用于 L2）
- **背景**：PC 版按 2 次 F10 屏幕右上角直接显示精确三维数字。新架构下它的用途变成「提供真值锚点」：
  当前读数与校准值一致 → 打印确认；不一致 → 拿校准值去全窗口搜对象并重建锁。
- **通信契约（重要）**：**必须走文件通道 `calibrate.json`**（GUI 调用 `api.Calibrate(x,y,z)` 写入，核心在 `tick()` 里轮询消费、读完即删）；**不要走 HTTP `/rescan`**（端口/未启动都会失败）。
- **匹配算法**：L2 全窗口扫描 → 三维容差 0.05 匹配 → 校验 `+0x120` 自指或 `+0x00` 静态指针确认身份 → 回填缓存槽。

### 5. 进程退出快速检测
- 采用 Windows API `GetExitCodeProcess` 快速探测（`exitCode != STILL_ACTIVE`），游戏一关立即释放句柄并回到等待状态，不卡死进程。

### 6. 定位缓存文件
- 程序目录下 `xnavi-pc-chain.json`：存构建指纹 + 静态槽位 + 坐标字段偏移。
- 删掉它不急，下次启动会自动走静态区重找并重建；换游戏版本时它是自动失效的（指纹不匹配）。
- **缓存里的坐标字段必须是 `0xD8`**；程序不认别的值（看到别的值会直接丢弃缓存重找）。
  `0xD8` 是根据实测结构定死的，**不要设计"自动学习偏移"**——2026-11-06 踩过坑，见文档避坑 15。

## 参数

| 参数 | 作用 |
|---|---|
| `--port=N` | 起始端口（默认 8766，被占时自动顺延到 8770） |
| `--save-dir=DIR` | 手动指定存档目录（默认取游戏 exe 同目录 `save/`） |
| `--pid=N` | 手动指定游戏进程 PID（自动发现失败时使用） |
| `--tls` | 同端口启用 http+https，需 `certs/server.pem` 与 `server.key` |
| `--tls-cert-dir=DIR` | 证书目录（默认 `certs`） |
| `--no-open` | 启动时不自动打开浏览器 |
| `--watch` | 控制台实时打印坐标 |
| `--debug` | 打印进程发现诊断日志 |
| `-h` / `--help` | 显示帮助 |

## 配套功能

- **定位**：固定地址直读，零全内存扫描、无需存档锚点、无需走两步确认，开局秒锁。
- **地图**：`/pos` 实时坐标、轨迹、跟随、导航目标（`/target`）、图层配置（`/config`）、重新定位（`/rescan`）。
- **存档**：`/save` 直传 `game_data.sav` 二进制供网页全量解析；`/progress` 输出 1078 个参考点、5 类可收集点与 12 项扩展统计；`/open-save`、`/save-override`。
- **手机镜像**：局域网访问 `http://IP:8766/botw/?follow=1&game=botw`，状态页可一键复制链接。
- **状态**：内嵌状态页 `/status`、运行时 `status.json` 健康快照。

## 兼容性说明

- `/pos` 的 `app` 字段固定为 `xnavi`。网页端口发现只认这个指纹，**不要改**，否则新程序配老网页会失联。
- 所有响应带 CORS 与 Private Network Access 预检头，在线 HTTPS 页面也能连本机服务。
- 读存档一律使用带 `FILE_SHARE_DELETE` 的 Win32 只读句柄，读完立即关闭，不会挡住游戏保存（避免 error 5 丢档）。
- 存档与现有 BOTW `game_data.sav` 完全同构，网页 `save_upload.js`、存档修改器等都不用改。

## 构建与测试

```bash
# 编译命令行核心
go build -trimpath -ldflags "-s -w" -o xnavi-pc.exe .

# 编译 GUI 核心
go build -trimpath -ldflags "-s -w" -o xnavi-core.exe .

# 端到端集成测试（需要 Savage Wind 正在运行）
go test -run TestIntegration -v

# 单测验证三维校准定向匹配
go test -run TestExactCoordHit3D -v
```
