# 旷野之息 · 存档修改（save-edit）

BOTWmap 子页。纯静态、无构建、`file://` 直接开；存档只在浏览器内存里处理，不上传。

入口：`save-edit/editor.html`（BOTWmap 侧栏「🛠 修改存档…」会带 `?v=11` 打开）。

## 五个模块

| # | 模块 | 内容 |
|---|---|---|
| 01 | 存档信息 | 游戏时长（只读）、卢比、生命上限、精力上限、克洛格果实（背包持有）+ 文件/版本/平台/物品统计 + **存档转换**（见下） |
| 02 | 材料和道具 | 食材 / 怪物素材 / 矿石宝石 / 虫与生物 / 其他 / 箭矢，数量 0–999 |
| 03 | 料理和药物 | 料理 / 药物，数量 0–999 |
| 04 | 装备强化 | 武器 / 弓 / 盾；附加属性类型、数值、耐久（单列/双列，卡片固定 320px） |
| 05 | 坐标瞬移 | 实验：改 X/Y/Z，读档后生效；默认关闭，需手动启用 |

## 转换存档（v1.7.4 · 测试中）

01 存档信息 →「存档文件」卡片下方。**标注「测试中」**：转换前先备份目标槽，转换后进游戏确认进度/物品/装备无误再继续。

- 载入后自动识别版本与平台，**下拉选择导出格式**：`Wii U · v1.5.0` / `Switch · v1.6.0` / `Switch · v1.9.0`（与源相同的格式不列出）；产物文件名带平台+版本（`game_data_cemu_v1.5.sav` / `game_data_switch_v1.6.sav` / `game_data_switch_v1.9.sav`）。
- 生成规则：目标版本号 + 目标 hash 序列作骨架，值按 hash/出现次序搬运；**35 张字符串表**（物品名、马名、相册地名、amiibo 记录等）原样复制，其余数值按目标端字节序翻转。
- 版本差异（真机存档实测）：1.6 比 1.5 多 `Ichigeki_Pedestal_Appear`；1.9 比 1.6 多 4 条 flag（`0x62133C14` / `0x8DAFA42C` / `0xCF031EFD` / `0xFA050B46`，值均为 0，1.6 romfs 里无名称）。降级时丢弃、升级时补 0。
- **旧版本（1.0–1.4）**：下拉里只有「保持源版本（只换字节序）」——换成目标平台后，由目标端游戏读档时自行升级（官方原生行为）。「保持源版本」只往 Switch 方向提供（Wii U 官方最高 1.5.0）。
- **版本事实**：Switch 最新为 **v1.9.0**（2026-02-17；1.8.0 起支持 Switch 2 Edition），本工具支持 **v1.5 / v1.6 / v1.9** 互转；1.8.x 少见、暂无样本，未适配。
- 转换包含**当前编辑态**（未导出的修改一起导出）；源文件不动，走浏览器下载。
- 覆盖前必须**完全关闭模拟器**；Cemu 槽位路径见下方「改了没反应」。
- 核心逻辑在 `save-convert.js`（UMD，Node 可直接 `require` 做回归）。

## 从 xnavi 读取最新档

xnavi 已有 `GET /save`，返回当前最新存档字节 + `X-Save-Path`（Eden/Cemu 取 mtime 最新槽，Ryujinx 取最高 playtime）。

- 推荐用 xnavi 自己托管的本地页打开，同源、不用处理跨域：
  `http://127.0.0.1:8766/botw/save-edit/editor.html?v=11`
- 点左侧「从 xnavi 读取最新档」；成功后显示 `xnavi · 槽 N · 游戏时长`，确认是不是刚存的档。
- 游戏刚保存后等 1–2 秒，xnavi 的 progress watcher 是 2 秒轮询。
- 直接双击 `editor.html`（`file://`）时浏览器禁止连本机 8766，页面会提示用上面的本地页。
- 从部署站 `https://botw.yalin.site` 打开时走 `http://127.0.0.1:8766/save`；跨域未暴露 `X-Save-Path`，只显示游戏时长，不显示槽位。
- xnavi 只负责读，不写；导出仍然下载 `game_data.sav`，自己覆盖对应槽。

## 边界

- 只写白名单：卢比、最大心心、最大耐力、现有物品数量、现有装备的 `FLAGS_*` / `FLAGSV_*`、克洛格果实（特例）、坐标（实验开关开启时）。
- 不改物品名、物品 ID、防具、重要物品、马匹、任务/神庙/事件标记。
- 导出前 `validateDiff()` 逐字节比对；白名单外有任何变化直接中止。
- 不覆盖原文件：“备份原档”下载 `game_data_original.sav`，“下载修改档”下载 `game_data.sav`，由用户手动替换。

## 两个特殊点

1. **克洛格果实**：读的是背包 `Obj_KorokNuts` 数量，不是 `KOROK_SEED_COUNTER`。如果背包里没有（比如全交给伯库林了），模块 02 会显示“放入 1 个（特殊）”；这是唯一允许添加物品的特例，需二次确认。
2. **坐标瞬移**：改的是存档坐标，导出后读档才生效，不是运行时瞬移。只支持 `MainField`；默认不写入，勾选“启用坐标修改”并点“应用坐标”才进白名单。坐标错误可能掉入虚空/水中。

## 文件

- `editor.html` / `editor.css`：暖褐 + 亮金双栏面板 + 五模块
- `botw-core.js`：存档解析 / 改写 / 白名单校验
- `save-convert.js`：Switch ↔ Wii U 存档转换（目标版本骨架 + 字符串表原样搬运 + 自校验）
- `botw-data.js`：物品名、分类、附加属性、耐力档位
- `botw-icons.js` + `assets/`：物品图标精灵（含 `Other.png` 箭矢）
- `marc-file.js`：二进制读写（Marc Robledo 实现移植）

## 界面约定

- **配色**：暖褐底（`#17130e`）+ 亮金（主金 `#c8952f` / 高亮 `#e7c46a`）。
- **布局**：左栏固定（存档卡 / 五个模块 / 打开存档 / 从 xnavi 读取 / 备份 / 还原 / 下载）；右侧模块工作区**铺满可用宽度、内容左对齐**，不再居中限宽。
- **改动明细**：主区顶部**吸顶金条**，有改动才出现、**默认折叠**（只留一条），点开展开核对；按「基础数值 / 材料和道具 / 料理和药物 / 装备强化 / 坐标瞬移」分组列「原值 → 新值」，每行带「撤销」按钮可**只还原这一项**（撤销时保留滚动位置）。数据源与导出摘要共用同一份清单（`collectChanges()`），不会漏项。
- **材料和道具 / 料理和药物**：紧凑图标网格（列数随宽度自适应，桌面 7–12 列、手机 3 列），每格「图标 + 名称 + −/数量/+」加一行 `+10 / +100 / 满` 快捷步进，改过的格子描金边；同名物品在名称下用 `#槽号` 区分。搜索是**跨全部类别**的，搜索时分类 Tab 不再高亮，框内带 `×` 一键清空。
- **装备强化**：卡片**固定 320px 宽**、左对齐自动换行（单列 392px），不会随屏幕拉宽；保留「附加属性下拉 / 数值 / 耐久滑块+数字+满」；切换附加属性只就地更新这张卡（不重建列表、不丢焦点）；顶部有「耐久全满」把本类装备一次设 100%（可逐项撤销）。
- **图标**：精灵图格子恒为 64×64，但**列数每张表不同**（苹果 12 列、矿石 10 列、鱼 15 列…），切片按 `botw-icons.js` 的 `SPRITE` 实际尺寸换算；图标尺寸由内联 style 决定，CSS 不要再改它的宽高。

## 自检（开发时）

用 v1.1 Wii U 样例存档跑过：

- 309 件物品；20 武器 / 13 弓 / 13 盾 / 6 箭 / 26 料理 / 136 材料。
- 弓槽 23 → 分类本地序号 3；写五连射只改 2 个字节，重新载入值正确。
- 耐久 50% → 32750；100% → 65500。
- 克洛格缺失 → 放入 1 个 → 可改 0–900；白名单校验通过。
- 坐标写入/还原：写入 `F-5`，取消启用后回到 `E-8`，diff 归零。
- 白名单外改动物品名首字节 → `validateDiff().ok=false`，导出中止。
- xnavi `/save` 实测：返回 1 号槽（`X-Save-Path` → `...\1\game_data.sav`），页面按钮同源读取成功；`file://` 打开时正确提示改用 `127.0.0.1:8766/botw/save-edit/editor.html?v=11`。

改静态资源后记得 bump `editor.html` 里的 `?v=` 和 BOTWmap 侧栏入口的 `?v=`（EdgeOne 长缓存）。

预览：`preview.png`（桌面装备页）/ `preview-mobile.png`（手机材料页）。

## 改了没反应？按顺序查

1. **先把下载的 `game_data.sav` 重新拖进编辑器**，看目标值是否还在（例如古代箭 = 913）。在 = 文件写对了，问题在替换/槽位；不在 = 下载的不是修改档。
2. **完全关闭 Ryujinx / Cemu / Eden**，再覆盖对应槽位的 `game_data.sav`。游戏运行中替换会被退出保存覆盖。
3. 确认覆盖的是**模拟器实际读取的存档**，不是 `game_data_work.sav`、备份、下载副本或别的槽位。
   - Ryujinx：`%APPDATA%\Ryujinx\bis\user\save\0000000000000008\0\<槽位>\game_data.sav`
   - Cemu：`%APPDATA%\Cemu\mlc01\usr\save\00050000\101c9300\user\80000001\<槽位>\game_data.sav`
   - Eden / Yuzu：`...\user\nand\user\save\...\<title id>\<槽位>\game_data.sav`
   - **Eden / Yuzu 的 0–7 是不同存档槽**：用游戏内读档界面的“游玩时间”对照编辑器「存档信息」里的游戏时长，选当前那个槽；改错槽位不会生效。
   - 日版 `101c9300`；美版 `101c9400`；欧版 `101c9500`。
4. 启动游戏后**读档**，不要先覆盖保存；看箭矢数量。
5. **手动存档同目录可能还有 `game_data.savbak`**：先备份它，再把下载的 `game_data.sav` 复制一份命名为 `game_data.savbak`，重启 Eden 再读。游戏在检测到主档异常时可能回退到备份，表现就是“主档里明明是 913，游戏里还是 13”。
6. 编辑器载入非 `game_data.sav` 文件名时，左侧会显示「非标准文件名」警告；这是提醒你它很可能不是模拟器实际存档。
7. 下载被浏览器拦截时，地址栏右侧会出现下载图标，允许后再试；另外不要用即时存档（save state）验证，读游戏内存档。
