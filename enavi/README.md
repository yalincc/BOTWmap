# Enavi —— Eden / 旷野之息 只读实时大地图伴侣

给 `https://botw.yalin.site` 喂坐标的本地小服务：在 Eden 里玩《旷野之息》时，
把林克的 **X / alt / Z** 实时推到地图上，并联动附近的神庙与克洛格。
（朝向不输出 —— 前端 `live.js` 已用位移推算箭头并做最短弧平滑，老大定的，精度够用且更稳。）

完整方案：[`PLAN.md`](./PLAN.md)

## 三条红线

1. **纯只读**：只申请 `PROCESS_VM_READ`，不写内存、不注入、不改存档；
2. **不碰网页**：Enavi 只提供 HTTP 数据，`app/` 一行不改（协议 v1 与现有前端兼容）；
3. **不依赖 Eden 调试功能**：生产路径只用 `ReadProcessMemory`。
   （实测 Eden 0.2.1 的 GDB Stub 残缺 —— 开启后游戏会卡在加载画面，只能当事故排查工具。）

## 定位原理与核心规范

完整技术手册与辟谣台账详见：[`docs/spec/ENAVI-HANDBOOK.md`](../docs/spec/ENAVI-HANDBOOK.md)

Enavi 读取的是林克在 3D 大世界中的主变换实体（`sead::Matrix34f`）：
- **坐标字段**：`+0x00` Vector3f (X, alt, Z)
- **Actor 充要特征**：`+0x0C` 紧随 36 字节 `sead::Matrix33f` **正交旋转矩阵**（三列向量单位模长且两两点积为 0）
- **绝不读取死数据**：强制拦截无 3x3 矩阵的静态存档缓冲，游戏加载期自动等待进世界，绝不早鸟抢跑
- **多候选走动仲裁**：驿站等多 NPC 密集区初始暂选最近 Actor，玩家一推摇杆走动（位移 > 0.5m）100ms 自动切换真林克
- **传送自适应换锚**：跨区长传送旧地址注销读失败时，自动比对磁盘最新传送存档自适应接管，秒级重新捕获新林克

## 老实说：它和 xnavi 的关系

**方法上是同一类** —— 都是「扫内存认坐标槽」。Enavi 没有跳出这个框，
老大一开始要的是「基址 + 固定偏移」（跨会话不变），**那个没做成**（详见 PLAN.md §14）。

**唯一的实质差别是稳定性**：

| | xnavi | Enavi |
|---|---|---|
| 定位方法 | 扫描 | 扫描（同类） |
| 状态机 | 探针池 / 候选分级 / 半死槽换锁 / 乒乓淘汰 / 失败组登记 | **只有 3 条失效规则** |
| 参数化机制 | 一大堆 | 无（采样频率写死） |
| 朝向解算 | 有 | 无（前端位移推箭头） |

老大嫌 xnavi「bug 没断过」，根因是机制太多互相打架。
Enavi 的价值是**用极简状态机把这类 bug 的土壤去掉**，不是方法更新。

### 已知限制与使用建议

1. **每次重开 Eden 要重新定位一次**（十几秒）—— 坐标槽地址随会话变，这是扫描类的宿命
2. **定位时需要在游戏里走动** —— 靠「位置明显移动」区分玩家和 NPC 位置表（站着不动时认不出，这是设计取舍：宁可显示"定位中"，也不返回一个假坐标）
3. **彻底废除磁盘地址缓存**：纯动态扫描锁真身，约 2~3 秒秒级出点，杜绝跨版本/跨会话僵尸地址毒化；
4. **存档过旧时需用户配合**：若玩家跑动很远（>150m）但游戏未自动存档，窄窗扫描未命中时，在游戏内**按【+】手动存个档**，或在 GUI 点**【手工校准】**输入当前大致 XZ 坐标定向找人。

## 为什么它比 xnavi 稳

xnavi 的 bug 不是算法不聪明，而是**机制太多互相打架**（探针池、半死槽换锁、候选分级、乒乓淘汰…）。
Enavi 只留三件事：

1. **锁定真身就死读**：实测 Eden 内存中林克坐标采样槽在传送、进出神庙全生命周期内地址不变，死读即可，严禁激进换锁；
2. **真身硬门禁（Run >= 2）**：林克真实采样环形缓冲固定 32~33 槽（Run=33），黑屏和参数表均为 Run=0，未进 3D 世界绝不抢跑；
3. **传送与神庙确定性**：传送落地直接接受新坐标零重扫；进神庙钉在门口保持在线，出神庙无缝接管跟随；
4. **不搞过度猜测算法**：找不到人时明确指引用户按【+】存盘或手工校准，保持代码极简。

站着不动、跑动、骑马、开菜单 —— **一律不重扫、不换锁**。

> 朝向不做：网页地图只需要坐标，前端 `live.js` 已用位移推算箭头并做了最短弧平滑，精度够用且更稳。

## 日常使用：双击 `M1.bat`

> **推荐用 GUI**：[`enavi-gui/`](../enavi-gui/) 是本项目的桌面测试界面
> （Wails + Vue 深色主题），把「锁的地址 / 扫描次数 / verified / 神庙挂起 /
> 实时日志」全部摊开在界面上，排查问题比盯黑窗口快得多。
> 核心的 exe 放 GUI 同目录即可；两者通过 `status.json` / `enavi.log` /
> `rescan.req` 三个文件通信，**不依赖 8766**，双入口互相独立。

双击 `M1.bat` 后它会：
1. 起一个只读的定位服务（`127.0.0.1:8766`）；
2. 自动打开 `https://botw.yalin.site/?follow=1&game=botw`；
3. 地图上的红点就开始跟林克走，转身时会带方向。

首次启动全堆动态扫描定位（约 2~3 秒秒级锁定）。
红点不动 / 显示"定位中"时：在游戏里**走两步**（定位靠「位置会变」来确认是玩家，不是 NPC 位置表），
或者关掉重开。窗口别关，关了服务就停了。

## 常见问题与快速定位技巧 (Q&A)

### Q: 启动后一直显示「定位中」或搜不到林克，怎么快速锁定？
**A: 最简单直接的方法：在游戏内原地按【+】手动存个档，然后重新开始定位（或点击重新扫描）。**
- **原理**：定位器默认以游戏最新的磁盘存档为中心开启 120m 窄窗定向秒找林克。如果你在游戏里已经跑出去很远（超过 150m），但游戏一直没有触发自动存档，定位器在旧存档附近自然搜不到人。
- **解决方式**：
  1. **首推（极简直接）**：在游戏里直接按【+】手动保存一次游戏，随后点【重新扫描】（或在 GUI 点【重新开始定位】），定位器瞬间以你脚下最新存档为中心 2~3 秒精准锁定真身！
  2. **备选（手工校准）**：在 `enavi-gui` 中点击【手工校准】，输入你当前大概的 X / Z 坐标（或点击【平原之塔 / 复苏神庙】等快捷预设），核心即可定向秒级捕获林克。

## 体检模式：双击 `M0.bat`

**双击 `M0.bat`**，跟着窗口里的提示走就行：

1. 它先等你把游戏跑起来（进游戏、读到存档、人物能走动）；
2. 然后自动测内存布局、找身份锚点；
3. 中间会让你回游戏里**走 10 秒**，回来按一次 Enter；
4. 最后自动打开 `report\` 文件夹，把那个 `M0-时间.log` 发回来即可。

全程只有"在游戏里做动作 + 按 Enter"两类操作，不用改 Eden 任何设置。
想中止：输 `q` 再回车。

| 步骤 | 测什么 | 为什么重要 |
|---|---|---|
| 1 | 等进入游戏 | 空载时 User Heap 是空的，测什么都是空的 |
| 2 | DRAM 大块 / User Heap 形态 | 决定 ASLR 怎么反解、扫描范围多大 |
| 3 | `Player` / `GameROMPlayer` / `1.6.0` 字符串 | 决定"身份锚点"这条路成不成（要排除 romfs 干扰） |
| 4 | 走动采样（无锚点找玩家槽） | 不用坐标就能指认玩家槽，是 M1 冷启动的关键 |
| 5 | 候选邻域的四元数 → 朝向 | 决定箭头能不能直接读出来 |
| 6 | GDB Stub 探测 | 只为证明它不能当实时通道；没开就跳过 |

分项命令、每项判据、台账表格见 `PLAN.md` §5。
