# 版本报告模板

> 每个版本（含已回档的）一份报告，落点 `docs/releases/V{X.Y.Z}.md`。
> 结构固定为以下 7 节，写完才算版本关闭；回档的版本同样要写（结论改为"已回档"并说明原因）。
> 配套：变更明细写 CHANGELOG.md，用户反馈台账写 tools/FEEDBACK.md（本地）。

## 模板结构

```markdown
# BOTWmap V{X.Y.Z} 版本报告（{YYYY-MM-DD}）

## 1. 版本概述
一句话目标 + 最终结论（已发布 / 已回档 + 原因）。

## 2. 发布内容
- 新增（用户可感知的，逐条对应反馈台账编号）
- 修复
- 变更/退役

## 3. 技术方案
- 数据源与管线（输入 → 生成 → 消费）
- 架构与关键算法（含口径定义）
- 关键决策（拍板记录与理由）

## 4. 踩坑记录
| 坑 | 根因 | 修复 | 教训 |
（每条一行；教训要可复用）

## 5. 测试与验收
- 测试清单与结果（专项 / verify / e2e）
- 用户实测反馈与处置

## 6. 遗留与后续
已知问题、待办、下版本候选。

## 7. 回溯
- commits（含废弃的）
- tag / 数据件位置 / 知识库指针
```
