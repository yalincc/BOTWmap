# BOTWmap V1.6.6 版本报告（2026-10-15）

## 1. 版本概述

**目标**：怪物层重建——换源官方缩放体系（LevelSensor），根治"地图显示游戏里不存在的怪"（幽灵怪），实现"地图显示你这个存档下真实存在的怪"。

**结论**：**已回档**。代码与数据管线已完成且测试全绿（专项 9 + verify 100 + e2e 13），但上线后用户实测暴露多处联动问题（侧栏小怪行消失、世界档位显示 0、营地图钉全灭、武器显示英文代码），三连热修后收敛速度不满足预期，用户决定回档到 V1.6.5。数据管线与算法已验证正确，问题集中在**前端接线与初始化时序**，重做成本可控（见 §6）。

## 3. 技术方案

### 数据源与管线
- 输入：`romfs/enemy-scaling.json`（官方 LevelSensor 结构化：5 链门槛 / 50 计分 / 65 武器档位表）、`enemy-distribution.json`（4710 实例 radar mubin，带 spawn/sensorMode/chain/tierIdx/equip）、`enemy-distribution-by-tier/tier-0~3`（按档世界预计算）
- 管线：`source/build_botwmap_tiers.py` → `app/data/enemy-tiers/` 7 件（tier×4 ~1.35MB + quest/hardmode/scaling 小件）
- 口径：`px = x*2+12000, py = z*2+10000`；spawn 分流（normal/ichigeki/hardmode）；hot = 武器含 strong/element

### 世界档位算法（DATA-README §12 标准）
- 积分 = Σ killScores.point × Defeated_*_Num（crc32 反查；血月不重置只涨不跌）
- 链档 = 门槛 ≤ 积分的最大档（Lynel 39/56/84/88）；**普通模式 cap 3**（Gold = 大师模式第 5 档）
- worldTier = 最高链档；tier 文件已编码 max(布点档, 链档)（布点 Middle 在 tier-3 仍 Middle）

### 关键决策
- boss 类保留旧标记：讨伐绿勾 liveIds / #N 编号 / enemy_save 92 条匹配全依赖旧 id 稳定
- camp_weapons.js 保留：equip 卡武器→营地反查仍用旧源（v1.6.7 候选换源）
- Loc 口径：camps 的 `loc = [[px,py],...]`（嵌套刷点数组，与 clusterLocs/campsNearMarker 的既有口径一致）
