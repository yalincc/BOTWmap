# xnavi v3.2.0 版本报告（2026-10-22）

## 1. 版本概述
将 xnavi 重构为「分发调度器 + 垂直独立管道」架构，彻底物理拆分 Cemu、Ryujinx 与 Eden 专属管道。全盘吸收 Enavi「做减法、做简单高效」的核心哲学：
1. **Eden 核心 100% 对齐 Enavi**：User Heap 扫描 `Run >= 2` 真身门禁、锁定后死读 addr、传送零重扫直接采纳新落点、神庙本地尺度挂起、彻底废除 known 磁盘缓存；
2. **Ryujinx & Cemu 根源治理（死守锁定 addr，彻底根除主动掉锁）**：固定偏移跨会话恒定，彻底移除 `invalidN >= 10` 等主动 drop 锁逻辑；骑马、盾滑、过图黑屏平滑保持，动作结束瞬间秒级恢复实时跟踪；
3. **全端日志标准化**：三端统一生命周期与事件语法糖（`[attach]`, `[lock]`, `[track]`, `[warp]`, `[shrine]`, `[hold]`, `[lost]`），含地标名称，与《LOCATE-RULES.md》排查手册完全对齐；
4. **GUI 完备交互与用户引导**：完整保留手工校准（内置平原之塔、复苏神庙、哈特诺塔、哈特诺所四大快捷预设与 XZ 窄窗定向秒级找人）、重新扫描、清屏、导出诊断包、打开目录以及步骤条与状态卡，清晰自解释。

## 2. 发布内容
- **架构重构与管道解耦**：
  - 分发调度器（Dispatcher）与三大独立物理管道（`watch_cemu.go` / `watch_ryujinx.go` / `watch_eden.go`）彻底拆分，`watch.go` 代码行数从 1323 行精简至 250 行；
  - 各模拟器全生命周期自闭环，互不干扰；
- **Eden 核心升级（死守 lockedAddr，传送零重扫零掉锁）**：
  - 彻底删除 `known_eden_botw.json` 磁盘缓存，根除僵尸地址与假锁；
  - 增加 `Run >= 2` 真身门禁，加载期绝不抢跑假点；
  - 独立 `readEdenActor` 小端读 + `WorldCoordOK` 原语，原生支持地下神庙试炼场坐标；
  - **死守 lockedAddr**：彻底消灭过图黑屏超时主动掉锁（Kill timeout reset）；传送过图黑屏平滑 hold 上一帧，落地直接接管新坐标（`delta > 300m -> [warp]`），全链路零重扫，用户零多余操作；
  - 神庙试炼场内红点死钉门口，出神庙无缝接管；
  - 5 组走动仲裁，站桩不误换，走动 0.5m 秒锁定真林克；
- **Ryujinx & Cemu 减法优化**：
  - 固定偏移秒锁，取消错误的主动掉锁（reset）；
  - 遇到骑马、骑摩托车、盾滑（标志位 `u0=0, u1=1`）或切场景瞬态读空时，保持上一帧有效位置，绝不丢锁；下马或加载完成瞬间秒级接管；
  - 出神庙增加防抖判定，必须读到合法大世界坐标才退出挂起，彻底消灭过图黑屏丢锁；
- **GUI 交互升级与手工校准**：
  - 日志栏完整提供【清屏】、【导出诊断包】、【打开目录】、【手工校准】、【重新扫描】；
  - 手工校准弹窗支持输入目标 XZ，并提供【平原之塔 / 复苏神庙 / 哈特诺塔 / 哈特诺所】4 大地标快捷预设，150m 窄窗定向秒级找人；
  - 仅在极端异常时供用户一键协助，日常游玩与传送完全全自动；
- **标准化全端日志**：
  - 统一日志前缀：`[attach]` 模拟器附加、`[lock]` 首次锁定、`[track]` 走动仲裁、`[warp]` 传送跳变（含地标名）、`[shrine]` 进出神庙试炼场（含地标名）、`[hold]` 骑乘/过渡期平滑保持、`[lost]` 模拟器真正关闭退出；
  - 用户看日志即可依据手册秒级判断运行状态。

## 3. 踩坑记录与根本原因复盘
| 坑 | 根因 | 修复 | 教训与总结 |
|---|---|---|---|
| 多模拟器逻辑耦合在单一 1323 行循环中 | 补丁式增加 `if isEden` 分支，导致改动互相踩脚 | 彻底物理拆分为独立管道文件，调度器仅负责生命周期分发 | 架构方案先行，不同特性的平台坚决物理隔离 |
| Eden 假锁与僵尸地址拉扯 | 读取了旧会话写入的 `known_eden_botw.json` 磁盘缓存 | 彻底删除并停止读写磁盘 known 缓存，全部基于实时门禁扫描 | 动态内存分配平台严禁依赖跨会话绝对地址缓存 |
| Eden 传送后掉锁与误锁旧残影 | 传送过图黑屏持续 6~8 秒，代码擅自设置了 6 秒读失败主动掉锁并去重扫；由于掉锁时落地自动存档尚未写盘，重扫误用起点坐标，锁到了起点残留的旧 RingBuffer 导致死锁 | **死守 lockedAddr，彻底取消黑屏超时掉锁（Kill timeout reset）**：切场景黑屏平滑 hold 保持，落地直接接管新落点坐标（`delta > 300m -> [warp]`），零掉锁零重扫，用户零操作 | 锁定的地址在进程内始终值得信赖，严禁在黑屏过渡期自作聪明主动丢锁与盲猜重扫 |
| Eden 进神庙失效与传送失效 | 读内存走 `DecodeAt` 被底层 `gameValidTriple` 将神庙地下坐标误杀为非法 nil；触发了老 xnavi 的 25 拍超时重扫，拿旧存档去扫导致脱轨 | 100% 对齐 `enavi` 极简核心：改用独立 `readEdenActor` 小端直读 + `WorldCoordOK` 原语；锁定后死读 addr，传送与神庙绝不触发重扫 | 严禁套用有硬编码边界的老公共函数，成熟资产必须原汁原味接入 |
| Ryujinx 骑马/盾滑/骑车失效 | 骑乘与盾滑时 Transform 槽被复用为 `IsRiding=1`，旧代码试图搜坐骑实体（盾滑根本无实体），读空 10 拍（1秒）就主动 reset 掉锁，掉锁后因标志位未除而永远无法重新锁上 | **做减法，像 Eden 一样死守锁定 addr**：固定偏移恒定成立，只要进程在就不 reset；读空平滑 hold 上一帧，下马/落地下一拍立即恢复实时跟随 | 不要轻易做加法打补丁，固定偏移锁定后保持常驻即可解决一切行为复用问题 |
| 日志信息各端不一、排查困难 | 传送和神庙日志各管道格式不统一（有的带地标名有的不带），用户和开发者排查困难 | 全量规范跨三端日志前缀（`[attach]`, `[lock]`, `[track]`, `[warp]`, `[shrine]`, `[hold]`, `[lost]`），统一输出地标名称 | 规范日志是最好的自解释与排查工具 |
