# enavi-gui v0.1.1 版本报告（2026-10-22）

## 1. 版本概述
- **一句话目标**：Eden 模拟器（旷野之息）只读实时定位桌面端工具正式版，彻底废除僵尸缓存、真身硬门禁死卡 `Run>=2`、传送零重扫并支持 GUI 手工校准一键预设。
- **最终结论**：**已发布（本地交付）**。

## 2. 发布内容
- **新增**：
  - **手工校准弹窗**：支持手动填入林克大致 X / Z 坐标（并内置【平原之塔 / 复苏神庙 / 哈特诺塔】一键预设），150m 窄窗定向秒级搜索；
  - **常见问题指引 Q&A**：明确指引在游戏内按【+】手动保存一次并重新开始定位，以最新存档脚下为中心秒级精准找人；
  - **状态看板增强**：实时显示当前锁定地址（Hex）、验证状态（`verified`）、扫描计数与神庙挂起标记。
- **修复**：
  - **神庙掉线彻底根治（B1）**：进神庙挂起返回 `ok=true, verified=true`，红点钉在门口，消灭网页端判定离线并停轮询的恶性 bug；出神庙自动恢复世界跟随；
  - **传送零重扫（B2）**：跨区传送（位移 > 300m）直接接受新落点，保持 `addr` 持续死读，全链路 `scans=1`；
  - **驿站多 NPC 仲裁（B4）**：走动 1~2 步（位移 > 0.5m）100ms 内瞬间完成真身指认与换锁。
- **变更/退役**：
  - **彻底废除 `known_player.json`**：不再向本地磁盘写入物理地址缓存，根除跨版本与游戏重载时的僵尸地址假锁；
  - **废除降级放行逻辑**：严格要求 `RunLength >= 2`（排除黑屏期与参数表静态死数据）。

## 3. 技术方案
- **架构**：双入口独立。`enavi-gui`（Wails v2）通过 `status.json`、`enavi.log`、`rescan.req` 与定位核心 `enavi.exe` 解耦通信，不依赖 8766 端口。
- **扫描判据**：
  1. `WorldCoordOK`：排除非法、近零与引擎参数表退化数据；
  2. 单位模长四元数：识别 `0x40` 步长位置采样槽；
  3. `RunLength >= 2`：林克物理环形缓冲固定为 32~33 槽（Run=33），静态数据均为 Run=0。
- **关键决策**：“让用户多参与，程序保持极简”——拒绝过度复杂的超时轮换与微动猜测，未在存档附近命中时指引用户按【+】存盘或手工校准。

## 4. 踩坑记录
| 坑 | 根因 | 修复 | 教训 |
|---|---|---|---|
| 跨版本无法定位 | 磁盘存档过旧（玩家在 3780m，存档在 1834m），窄窗扫不到 | 提示用户游戏内按【+】手动存盘，或手工填入 XZ 坐标定向搜索 | 模拟器跨版本不要轻易怀疑编译器内存布局，先看物理输入（存档锚点）|
| 游戏重开后红点卡死 | `known_player.json` 磁盘缓存记录了旧地址，跨会话秒锁了僵尸槽 | 彻底删除 known 磁盘缓存读写，每次启动纯动态扫描 | 动态扫描只需 2~3 秒，不要为了省 1 秒引入持久化僵尸缓存风险 |
| 游戏黑屏期锁死假数据 | 扫描未命中时降级放过了 `Run=0` 的候选 | 严禁降级，死卡 `RunLength >= 2` 门禁 | 未进 3D 世界前宁可等待，绝不能抢跑出假点 |

## 5. 测试与验收
- **实测通过项**：
  1. Eden 0.2.1 与 clang 23.1.3 多版本冷启动扫描锁定（耗时 2~3s）；
  2. 走动仲裁切换真身（100ms 准确换锁）；
  3. 跨区传送（位移 > 3000m）零重扫无缝跟随；
  4. 进出神庙红点钉门口，网页端零掉线；出神庙平滑接管；
  5. 手工校准输入 XZ 坐标秒级窄窗定向搜索；
  6. 游戏内按【+】存盘后重新定位秒锁。
- **验收结论**：老大实测确认通过，核心定型。
